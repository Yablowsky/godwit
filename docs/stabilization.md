## Важные ограничения

- Обновление Swift-адаптера требует **пересоздания** Mobile.xcframework. Старый
  бинарный framework не подходит. Имена импортированных в Swift методов
  подтверждены сборкой против реального gomobile framework в CI.
- Новое ядро использует OLC2/OLVC5. Перед выкладкой проверить совместимость
  серверов, лучше на отдельном серверном экземпляре с целевым SHA. Этот патч
  не меняет серверы и не обновляет пользовательские профили автоматически.
- Runtime.Ping использует собственный контекст с таймаутом. Runtime.Stop его
  не отменяет. Отменённый результат отбрасывается после возврата probe, порт
  удерживается до этого момента. Мгновенная отмена пингов в этот этап не входит.
- В новом mobile API отсутствует SetLogWriter: внутри приложения остаются
  события жизненного цикла; подробные логи ядра нужно смотреть средствами ОС.
- Runtime.SetDebug остаётся process-wide, хотя сами подключения независимы.
- Stop ядра ограничен 5 секундами на попытку. Ожидание отключения в приложении
  ограничено 15 секундами. При таймауте приложение не утверждает, что VPN
  отключён, и оставляет возможность повторить Stop.
- Расширение не вызывает stop completion, пока нативные компоненты не вышли.
  Если native quit/Go shutdown зависнет, окончательный лимит жизни расширения
  задаёт NetworkExtension. Это не гарантия завершения C-кода за фиксированный срок.
- Нативный forwarder не предоставляет положительного события готовности:
  запуск подтверждает готовность ядра и настройку интерфейса; неожиданное
  завершение forwarder обнаруживается монитором. Полноценный readiness API
  требует отдельной доработки обёртки Tun2SocksKit.
- Фоновый local SOCKS на iOS всё ещё зависит от audio workaround. Устойчивую
  работу одновременно с Shadowrocket нельзя гарантировать без испытаний на
  устройстве. Это не новый always-on механизм и не исправление политики iOS.
- Проверить отдельно профили с локальной SOCKS-аутентификацией: существующий
  tun2socks YAML не передаёт socksUser/socksPass. Для первого тестового прогона
  использовать loopback SOCKS без этих полей.
- Восстановление статуса уже работающего VPN не означает поддержку нового
  запуска расширения из Settings/On Demand без start options: ключи сейчас
  не хранятся в provider metadata. Хранилище секретов между app/extension —
  отдельная задача.
- Не реализованы автоматический reconnect/backoff, обновление маршрутизации,
  полный UDP forwarding и переработка UI/подписок.
- Восстановление прежних настроек системного прокси macOS после изменения
  через networksetup — отдельная задача; сейчас отключается сервис,
  включённый текущим запуском Godwit, а не выбранный позднее в UI.

## Обязательная проверка на Mac / CI

Workflow `.github/workflows/validate.yml` выполняет Swift tests,
сборку Mobile.xcframework, iOS app +
Packet Tunnel, macOS app и standalone bundle. Strict-concurrency diagnostics
включены. Swift-предупреждения в unit tests и Xcode-сборках считаются ошибками,
чтобы новые concurrency diagnostics не могли незаметно пройти CI.

На Mac дополнительно выполнить `cd apple && xcodegen generate`, проверить diff
сгенерированного проекта, затем собрать оба приложения и extension. Здесь pin
в pbxproj обновлён точечно, генератор XcodeGen не запускался.

`AGENTS.md` требует успешную Xcode-сборку перед отправкой изменений в репозиторий.
Владелец разрешил выполнить этот gate через GitHub Actions после отправки
отдельной draft-ветки, без merge/release. До успешной сборки и проверки
диагностики PR должен оставаться черновиком.

Там же `context7` ошибочно описан как отменяемый Go-контекст и обязательный
аргумент запуска. В реальном API это `context.Context`, создаваемый внутри
Runtime.Start и отменяемый Runtime.Stop. Context7-инструмента в этой среде нет;
адаптер основан на исходниках API, не на несуществующем параметре. Сам AGENTS.md
в этом наборе не менялся.

## Ручная приёмка перед TestFlight

1. Выделенный тестовый сервер с согласованным ядром; существующий production
   сервер пока не заменять.
2. 100 циклов Start/Stop, в том числе Stop во время соединения; убедиться,
   что UI и Settings показывают одинаковый статус и порт освобождён.
3. Перезапуск приложения при активном VPN; отключение из системных Settings.
4. Wi-Fi ↔ LTE, авиарежим, отсутствие сервера, завершение transport/forwarder.
5. Запуск Shadowrocket сразу после подтверждённого отключения Godwit.
6. Отдельно local SOCKS: 12–24 часа с блокировкой экрана, нагрузкой и замерами
   памяти; повтор после принудительного закрытия приложения.
7. Проверка всех используемых provider/transport сочетаний и старых профилей.
